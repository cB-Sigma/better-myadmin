### Server tab bar (`src/Menu.php::getServerTabs`)

Tab order and visibility conditions (all routes relative to `index.php?route=`):

1. `databases` – icon `s_db`, `/server/databases` (always).
2. `sql` – `b_sql`, `/server/sql` (always).
3. `status` – `s_status`, `/server/status`; active for `/server/status`, `/advisor`, `/monitor`, `/processes`, `/queries`, `/variables`.
4. `rights` – `s_rights`, label "User accounts", `/server/privileges`; shown only if `isSuperUser() || isGrantUser() || isCreateUser()`; active also on `/server/user-groups`.
5. `export` – `b_export`, `/server/export`.
6. `import` – `b_import`, `/server/import`.
7. `settings` – `b_tblops`, `/preferences/manage`; active on all `/preferences/*` routes.
8. `binlog` – `s_tbl`, `/server/binlog`; shown only when `SHOW BINARY LOGS` returned rows (`! empty($binaryLogs)`).
9. `replication` – `s_replication`, `/server/replication`; superuser only.
10. `vars` – `s_vars`, `/server/variables`.
11. `charset` – `s_asci`, `/server/collations`.
12. `engine` – `b_engine`, `/server/engines`.
13. `plugins` – `b_plugin`, `/server/plugins`.

Tabs are then filtered by user-group permissions (`Menu::getAllowedTabs`): when the configurable-menus feature (pmadb `users` + `usergroups`) is enabled, the query `SELECT tab FROM <usergroups> WHERE allowed='N' AND tab LIKE 'server%' AND usergroup = (SELECT usergroup FROM <users> WHERE username = <cfg user>)` removes disallowed tabs (cached in session under `menu-levels-server`).

Privilege probes used throughout (`src/Dbal/DatabaseInterface.php`):
- `isSuperUser()` = `SELECT 1 FROM mysql.user LIMIT 1` succeeds (session-cached `is_superuser`).
- `isGrantUser()` = with `DisableIS` false: queries `information_schema.USER_PRIVILEGES` for `GRANT` on the current user; with `DisableIS` true: any `SHOW GRANTS` line containing `WITH GRANT OPTION` (cached `is_grantuser`).
- `isCreateUser()` = `CREATE USER` privilege or `ALL PRIVILEGES ON *.*` in grants (cached `is_createuser`).
- Nearly every server controller does `if (isSuperUser()) selectDb('mysql')` before rendering.

## Screens / components

### Status – shared frame (`server/status/base.twig`)

Purpose: pill navigation shared by the six Status sub-pages. Layout: `<ul class="nav nav-pills p-2">` with links Server (`/server/status`), Processes, Query statistics, All status variables, Monitor, Advisor; the active one gets `.active`; all links carry `disableAjax` (full page loads). Content block below.

Shared data object `src/Server/Status/Data.php` (constructed per request, injected into every Status controller):
- Loads `ReplicationInfo` (`load($_POST['primary_connection'])`).
- `SHOW GLOBAL STATUS` via `tryQuery`; failure → `dataLoaded=false` and every page shows a "Not enough privilege…" error.
- `SHOW GLOBAL VARIABLES` (always, for derived values).
- `cleanDeprecated()`: drops `Com_prepare_sql`, `Com_execute_sql`, `Com_dealloc_sql` when the `Com_stmt_*` counterparts exist.
- `calculateValues()` adds synthetic variables: `Key_buffer_fraction_%` (= `100 - Key_blocks_unused * key_cache_block_size / key_buffer_size * 100`, fallback `Key_blocks_used / key_buffer_size`), `Key_write_ratio_%` (= `100*Key_writes/Key_write_requests`), `Key_read_ratio_%`, `Threads_cache_hitrate_%` (= `100 - Threads_created/Connections*100`).
- `sortVariables()` maps each variable to a section via prefix table `ALLOCATIONS` (first match wins, `str_contains`): `Com_`→com, `Innodb_`→innodb, `Ndb_`→ndb, `Handler_`→handler, `Qcache_`→qcache, `Threads_`/`Slow_launch_threads`→threads, `Binlog_cache_`→binlog_cache, `Created_tmp_`→created_tmp, `Key_`→key, `Delayed_`/`Not_flushed_delayed_rows`→delayed, `Flush_commands`/`Last_query_cost`/`Slow_queries`/`Queries`/`Prepared_stmt_count`→query, `Select_`→select, `Sort_`→sort, `Open_tables`/`Opened_tables`/`Open_table_definitions`/`Opened_table_definitions`/`Table_locks_`→table, `Rpl_status`/`Slave_`→repl, `Tc_`→tc, `Ssl_`→ssl, `Open_files`/`Open_streams`/`Opened_files`→files, else `other`. Com_ variables with value > 0 become `usedQueries` (then `Com_admin_commands` is removed because admin commands are not counted in `Questions`).
- Section labels (`getSections`): com "Com", query "SQL query", innodb "InnoDB", ndb "NDB", handler "Handler", qcache "Query cache", threads "Threads", binlog_cache "Binary log", created_tmp "Temporary data", delayed "Delayed inserts", key "Key cache", select "Joins", repl "Replication", sort "Sorting", table "Tables", tc "Transaction coordinator", files "Files", ssl "SSL", other "Other".
- `getLinks()` – "related links" per section (rendered on the status-variables page): table → "Flush (close) all tables" (`flush=TABLES`), "Show open tables" (`/sql` with `sql_query=SHOW OPEN TABLES`, `goto`=root); repl → "Show replica hosts" (`/sql`, `SHOW SLAVE HOSTS`) and "Show primary status" (`#replication_primary`) if primary, "Show replica status" (`#replication_replica`) if replica, doc `replication`; qcache → "Flush query cache" (`flush=QUERY CACHE`), doc `query_cache`; threads doc `mysql_threads`; key doc `myisam_key_cache`; binlog_cache doc `binary_log`; `Slow_queries` doc `slow_query_log`; innodb → "Variables" (`/server/engines/InnoDB`), "InnoDB Status" (`/server/engines/InnoDB/Status`), doc `innodb`.
- `dbIsLocal` = host is `localhost`, `127.0.0.1` or `::1` (lower-cased compare for host).

### Status – Server overview (`/server/status`)

Purpose: uptime, traffic and connection summary plus replication status summary.

Layout (`status/status/index.twig`): `<h3>Network traffic since startup: {Bytes_received+Bytes_sent formatted}</h3>`, paragraph "This MySQL server has been running for %1$s. It started up on %2$s." then a two-table row.

Controls / content:
- Traffic table (col-md-5): header "Traffic" with hint "On a busy server, the byte counters may overrun, so those statistics as reported by the MySQL server may be incorrect."; columns `#` and `ø per hour`. Rows Received, Sent, Total; values `Util::formatByteDown(x, 3, 1)`; per-hour = value × `3600/Uptime`.
- Connections table (col-md-6): columns `#`, `ø per hour`, `%`. Rows: "Max. concurrent connections" (`Max_used_connections`, per-hour and % = `---`), "Failed attempts" (`Aborted_connects`, formatted `formatNumber(v,4,1,true)`, per hour `formatNumber(v*hourFactor,4,2,true)`, % of `Connections` with 2 decimals, `---` if Connections = 0), "Aborted" (`Aborted_clients`, same), "Total" (`Connections`, `formatNumber(v,4,0)`, per hour, `100%`).
- Replication block (only if primary or replica): alert `alert-primary` "This MySQL server works as **primary** and **replica** in **replication** process." (or primary-only / replica-only wording), `<hr>`, `<h3>Replication status</h3>`, then `ReplicationGui::getHtmlForReplicationStatusTable($primaryConnection, 'primary')` and/or `'replica'` (visible tables with titles "Primary status"/"Replica status"; see Replication section for variable lists and colouring).
- No data → `Not enough privilege to view server status.` error.

Server-side: `getStartTime()` = `SELECT UNIX_TIMESTAMP() - {Uptime}`, formatted with `Util::localisedDate`. Uptime via `Util::timespanFormat`. Note: in current master there are **no** flush/refresh links on this page; "Flush (close) all tables" / "Flush query cache" / "Show open tables" live in the *status variables* page's related-links box.

### Status – Processes (`/server/status/processes`)

Purpose: live process list with kill, sort, filter and auto-refresh.

Layout (`status/processes/index.twig`): card "Filters" with a POST form; the list table; a notice; refresh-rate selector + toggle link.

Controls:
- Checkbox `showExecuting` "Show only active" (class `autosubmit`); button "Refresh" (submits form). Hidden inputs: `ajax_request`, `full`, `column_name`, `order_by_field`, `sort_order`.
- Table `#tableprocesslist` (`list.twig`): first header "Processes" (kill column), then sortable headers from `Processes::getSortableColumnsForProcessList`: ID(`Id`), User(`User`), Host(`Host`), Database(`Db`), Command(`Command`), Time(`Time`), Status(`State`), Progress(`Progress`, MariaDB only), SQL query(`Info`). Each header is a `data-post` link (`sortlink`) carrying `column_name`, `order_by_field`, `sort_order` (ASC by default; if the column is currently sorted ASC, the link toggles to DESC), and `showExecuting=on` when filter is active. Sorted column shows asc/desc arrow icons (`ic_s_desc`/`ic_s_asc`, one hidden). Last column header additionally has the full/partial text toggle icon: `s_fulltext` "Show full queries" when truncated, `s_partialtext` "Truncate shown queries" when full; it posts `refresh_params` (`full` = 1 or '').
- Row cells: "Kill" link (`a.ajax.kill_process`, href `/server/status/processes/kill/{id}`, data-post `kill={id}`), id (monospace right), user (link to `/server/privileges?username=&hostname=&dbname=&tablename=&routinename=` unless user ∈ {`system user`, `event_scheduler`, `unauthenticated user`}; hostname has trailing `:port` stripped via `preg_replace('/:\d+$/')`), host, db (link to `/database/structure?db=` or `<em>None</em>`), command, time, state (`---` if empty), progress (MariaDB only; `---` if empty), info (`Generator::formatSql(info, truncate = !full)` or `---`).
- Notice: "Note: Enabling the auto refresh here might cause heavy traffic between the web server and the MySQL server."
- `select#id_refreshRate` options 2,3,4,5(default),10,20,40,60,120,300,600,1200 seconds; <60 shown as "%d seconds", ≥60 as "%d minutes".
- `a#toggleRefresh` with play icon "Start auto refresh" ↔ pause icon "Stop auto refresh".

Interactions (`processes.ts`):
- Kill: POST href with `ajax_request=1&server=`; on success remove the `<tr>`, re-stripe rows odd/even, show message "Thread %s was successfully killed."; else error "phpMyAdmin was unable to kill thread %s. It probably has already been closed."
- Auto-refresh: toggling sets `autoRefresh`, label/icon, and starts `refresh()` which aborts any pending request, POSTs `/server/status/processes/refresh` with `server, ajax_request, refresh, full, order_by_field, column_name, sort_order` (+ `showExecuting` if checked) — `full` is the hidden input's value (`''` when truncated) and RefreshController tests its presence, so refreshed lists are always `SHOW FULL PROCESSLIST` (quirk Q51); replaces `#tableprocesslist` innerHTML with the returned table, re-runs SQL highlighting, and schedules the next tick with `setTimeout(interval*1000)`. Changing the rate restarts immediately. Clicking any header link stores its href as `refreshUrl` (legacy; the refresh always posts to `/refresh`). Teardown aborts timers/requests.

Server-side (`Processes::getList`): base query `SHOW PROCESSLIST` or `SHOW FULL PROCESSLIST`; if `showExecuting` or a sort is requested, switches to `SELECT * FROM INFORMATION_SCHEMA.PROCESSLIST`; filter appends `WHERE COMMAND <> 'Sleep' AND STATE <> 'Waiting for next activation'`; sort appends `ORDER BY \`field\` ASC|DESC` (order_by_field is backquoted, sort_order inserted verbatim). Keys lower-cased. MariaDB progress: if `stage` and `max_stage` columns exist and `max_stage > 1`, progress = `(stage-1)/max_stage*100 + progress/max_stage` formatted to 3 decimals. Kill: `KILL {id};` or, on Amazon RDS as superuser, `CALL mysql.rds_kill({id});` (`getKillQuery`). Refresh/Kill endpoints return empty response when not AJAX.

### Status – Query statistics (`/server/status/queries`)

Purpose: per-statement-type counters with a pie chart.

Layout (`status/queries/index.twig`): `<h3>Questions since startup: {total}</h3>` + MySQL doc link (`server-status-variables#statvar_Questions`); list `ø per hour: n`, `ø per minute: n`, and `ø per second: n` only when ≥ 1. ### Status – Monitor (`/server/status/monitor`)

Server-side SQL (`Monitor.php`):
- Chart data: `SHOW GLOBAL STATUS WHERE Variable_name='a' OR Variable_name='b'…` and `SHOW GLOBAL VARIABLES WHERE …` (names filtered to `[a-zA-Z_]`); `proc` → `SHOW PROCESSLIST` row count; `cpu`/`memory` from `SysInfo::get()->loadavg()/memory()` (Linux reads `/proc/stat` first line and `/proc/meminfo` MemTotal/MemFree/Cached/Buffers/SwapCached/SwapTotal/SwapFree, derives MemUsed/SwapUsed; WindowsNt uses WMI; SunOs uses kstat; `Base` returns zeros).
- Slow log: `SELECT start_time, user_host, Sec_to_Time(Sum(Time_to_Sec(query_time))) as query_time, Sec_to_Time(Sum(Time_to_Sec(lock_time))) as lock_time, SUM(rows_sent) AS rows_sent, SUM(rows_examined) AS rows_examined, db, sql_text, COUNT(sql_text) AS '#' FROM mysql.slow_log WHERE start_time > FROM_UNIXTIME(s) AND start_time < FROM_UNIXTIME(e) GROUP BY start_time, user_host, db, sql_text`; INSERT/UPDATE texts > 220 chars are cut to 200 + `... [size]`; sums per statement type + TOTAL; `numRows`.
- General log: `SELECT TIME(event_time) as event_time, user_host, thread_id, server_id, argument, count(argument) as '#' FROM mysql.general_log WHERE command_type='Query' AND event_time > FROM_UNIXTIME(s) AND event_time < FROM_UNIXTIME(e) [AND argument REGEXP '^(INSERT|SELECT|UPDATE|DELETE)'] GROUP by event_time, user_host, thread_id, server_id, argument`; with `removeVariables`, consecutive `INSERT INTO <table>` rows are collapsed into the first one (count accumulated, `<br>...` appended).
- Log vars: `SET GLOBAL {name} = {value}` (name `[a-zA-Z0-9_]`, non-numeric quoted) then `SHOW GLOBAL VARIABLES WHERE Variable_name IN ("general_log","slow_query_log","long_query_time","log_output")`.
- Query analyzer: `selectDb(database)`, `SET PROFILING=1;` if supported, rewrite leading `SELECT` to `SELECT SQL_NO_CACHE`, run it, `affectedRows`, `EXPLAIN {query}`, `SELECT seq,state,duration FROM INFORMATION_SCHEMA.PROFILING WHERE QUERY_ID=1 ORDER BY seq`.
- All monitor endpoints return an empty response when not AJAX; superuser gets `selectDb('mysql')`.

### BetterMyAdmin additions: Dashboard and Slow queries

Not in phpMyAdmin (parity exceptions [X64, X65](../reference/parity-exceptions.md)); user docs: `docs-site/status_insights.rst`. Two more Status pills: **Dashboard** first, **Slow queries** after Query statistics; the Status tab still opens phpMyAdmin's Server page, and the UI parity map `tests/ui-parity/maps/_global.yaml` excuses the two pills (section-less links named `Dashboard` / `Slow queries`) on every Status case.

- **Dashboard** (`/s/:s/status/dashboard`, `DashboardPage.tsx`, logic in `features/server/dashboard.ts`): `GET /api/servers/:s/status/dashboard` (`server-admin/dashboard.ts`) returns `UNIX_TIMESTAMP(NOW(3))`, `SHOW GLOBAL STATUS WHERE Variable_name IN (…20 counters…)`, `SHOW GLOBAL VARIABLES WHERE Variable_name IN (version, version_comment, max_connections, innodb_buffer_pool_size, long_query_time, slow_query_log)` and `SHOW REPLICA STATUS` (`SHOW SLAVE STATUS` on older servers): `replica` is `null` (not a replica), `'denied'` (errno 1227/1045/1142/1044) or `{lag, ioRunning, sqlRunning}`. The browser computes rates from two readings (`computeMetrics`: Δcounter / Δserver time; a counter going down or `Uptime` going down gives no rate; the first reading's ratios are since startup), keeps 60 readings per card and polls every 2/5/10/30 s via `refetchInterval`, stopped by the pause button and while `document.visibilityState` is `hidden` (the series breaks there). Thresholds (`THRESHOLDS`): connections ≥ 80/95 % of `max_connections`; buffer pool hit rate < 99/95 %; temporary tables on disk ≥ 25/50 %; slow queries ≥ 1/10 per minute; table locks waited ≥ 0.1/1 per second; replication lag ≥ 30/300 s, a thread not `Yes` or an unknown lag is critical. Status unreadable → "Not enough privilege to view server status."; replica status denied → a note, the other cards stay.
- **Slow queries** (`/s/:s/status/slow-queries?source&db&sort&order`, `SlowQueriesPage.tsx`; `server-admin/slow-queries.ts`): `GET …/status/slow-queries` reads the top 100 of `performance_schema.events_statements_summary_by_digest` (`ORDER BY` an allow-listed column, `SCHEMA_NAME = db`; `QUERY_SAMPLE_TEXT` only when `information_schema.COLUMNS` lists it, so MySQL 5.7 / MariaDB work), or `source=slowlog`: the newest 10,000 rows of `mysql.slow_log` grouped in Node by (db, `normalizeQuery`: literals → `?`, `IN (…)` / multi-row `VALUES` collapsed, keywords upper-cased, comments dropped). Unavailable reasons: `pfs-off` (`performance_schema` OFF, MariaDB's default), `pfs-denied`, `digest-consumer-off`, `log-not-table`, `slow-log-off`, `slow-log-denied`, each shown with how to enable it and a MySQL/MariaDB manual link. `canReset` = `SHOW GRANTS` gives DROP on the table (`*.*`, `performance_schema.*` incl. wildcards, or the table; roles not followed). `GET …/slow-queries/detail?digest&db` → text, `formatSql` of it, a sample (`QUERY_SAMPLE_TEXT`, else `events_statements_history_long`, then `events_statements_history`, or the slow log's newest), `explainable`. `POST …/slow-queries/explain {db, query}` runs `EXPLAIN <stmt>` on a connection of its own (after `USE db`) only when the lexer finds a single SELECT/WITH/INSERT/UPDATE/DELETE/REPLACE/TABLE statement (anything after a delimiter is refused). `POST …/slow-queries/reset` → `TRUNCATE TABLE performance_schema.events_statements_summary_by_digest` (confirmation first).

5. `getRequireClause`: `ssl_type` `SPECIFIED` → `REQUIRE CIPHER '…' AND ISSUER '…' AND SUBJECT '…'` (non-empty ones; none → `REQUIRE NONE`), `X509` → `REQUIRE X509`, `ANY` → `REQUIRE SSL`, else `REQUIRE NONE`. `getWithClauseForAddUserAndUpdatePrivs`: ` GRANT OPTION` (only pre-8.0.11), `MAX_QUERIES_PER_HOUR n`, `MAX_CONNECTIONS_PER_HOUR n`, `MAX_UPDATES_PER_HOUR n`, `MAX_USER_CONNECTIONS n` (ints clamped ≥ 0) → ` WITH …`.
6. `addUserAndCreateDatabase`: on error → raw MySQL error; success "You have added a new user."; `createdb-1` → `CREATE DATABASE IF NOT EXISTS \`u\`;` + `GRANT ALL PRIVILEGES ON \`u\`.* TO …;` (username wildcard-escaped) and navigation reload with the new db selected; `createdb-2` → `GRANT ALL PRIVILEGES ON \`u\_%\`.* TO …;`; `createdb-3` → `GRANT ALL PRIVILEGES ON \`dbname\`.* TO …;`.
7. `userGroup` posted + menus feature → `setUserGroup`.
8. AJAX response adds `new_user_string` (a `new_user_ajax.twig` row to insert into the overview), `new_user_initial`, `new_user_initial_string`, and `sql_query` HTML.

Reproduced phpMyAdmin quirks (user accounts; checked against the reference, kept for statement parity unless noted)
- No `grant_count` posted → every posted privilege counts as "all of them": the GRANT says `ALL PRIVILEGES`.
- **Fixed, exception X40** ([#19605](https://github.com/phpmyadmin/phpmyadmin/issues/19605)): on MySQL/Percona ≥ 8.0.11 "Update user privileges" with Grant_priv=Y moves the WITH clause to `ALTER USER` (an empty `ALTER USER 'u'@'h' ;` at database, table and routine level), which drops GRANT OPTION, and the GRANT never gets `WITH GRANT OPTION`. We append ` WITH GRANT OPTION` to the GRANT at every level; the ALTER USER is phpMyAdmin's, byte for byte.
- A routine of a database whose posted name carries escaped wildcards (`f06u\_db`): `getRoutineType` looks it up with the escaped name, finds nothing, and the GRANT / REVOKE with an empty item type fails (phpMyAdmin dies with the MySQL error; so do we).
- Copy user (modes 1–4) does not escape backquotes in column lists (`SELECT (`c`q`)`: broken SQL) and does not copy the global privileges (only GRANT USAGE).
- "Do not change the password" (`pred_password=keep`) on MySQL 8 sends the stored hash as the new clear-text password.
- `updatePassword`'s MariaDB branch tests `>= 10000` (always taken on MariaDB).
- The db / table links under the editor (`user_properties.twig`) are shown only at table level.
- Check-all boxes: a group box is checked when any of its boxes is; group boxes never follow the individual boxes.
- The edit pages always render the sub-navigation pills (`addOrUpdateSubmenu`), even for one section; the copy form appears at every level; the Generate-password row is appended at the end of the login card; disabled initials are `<a href="#">`.
- MySQL 8.4 (server behaviour, not phpMyAdmin): `REVOKE ALL PRIVILEGES ON *.*` also removes table, column and routine grants.
