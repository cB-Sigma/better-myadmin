Export/Import tabs are only pointed to. All statements below are derived from the phpMyAdmin `master` source (Oct 2026) at `src/`, `resources/templates/`, `resources/js/`. Each feature cites the controller / class / template / JS that implements it so a clone can be verified against the original. No behaviour is invented.

### Config directives touched by this area (name = default; source `src/Config/Settings.php` unless noted)

- `ShowColumnComments = true` — show "Comments" column in Structure list.
- `ShowPropertyComments = true` — load pmadb column comments / MIME for the Structure page tooltips (`StructureController::displayStructure`).
- `HideStructureActions = true` — collapse per-row action links into a "More" dropdown.
- `ShowStats = true` — show Space usage / Row statistics card.
- `DefaultTabTable = 'browse'` (route `/sql`; allowed: `/table/sql`, `/table/search`, `/table/change`, `/sql`, `/table/structure`) — used as `goto` after Search/Zoom/Find-Replace/Chart and as link target in Privileges heading.
- `NavigationTreeDefaultTabTable = 'structure'`, `NavigationTreeDefaultTabTable2 = ''`.
- `TableNavigationLinksMode = 'icons'` (`both|icons|text`) — rendering of browse navigation links (Browse grid, out of scope, listed for completeness).
- `ActionLinksMode = 'both'`, `TabsMode = 'both'` — icon/text rendering of action links / tabs (`show_icons('ActionLinksMode')` toggles the structure "Action" `colspan` 8 vs 9).
- `DisableMultiTableMaintenance = false` — refuse Analyze/Check/Checksum/Optimize/Repair when more than one table is posted.
- `ShowCreateDb = true` — (database-level create box; listed because asked).
- `BrowseMIME = true` — show Media type / transformation columns in column form and Structure type cell.
- `CharEditing = 'input'` (`input|textarea`) — default value and expression inputs rendered as `<input>` vs `<textarea>`.
- `ReservedWordDisableWarning = false` — skip `/table/structure/reserved-word-check`.
- `MaxDbList = 100` — Move/Copy target DB shown as `<select>` only when DB count ≤ MaxDbList, otherwise text input.
- `MaxRows = 25` — default "Number of rows per page" in Search.
- `MaxRowPlotLimit` (`config->maxRowPlotLimit`, default 500 in settings) — default "Maximum rows to plot" in Zoom search.
- `LimitChars = 50` — long column type strings in Structure are abbreviated with `<abbr>`.
- `InitialSlidersState = 'closed'` (`open|closed|disabled`) — collapsibles: Partitions, Index "Advanced options", Search "Extra options", Relation "Internal relationships".
- `NaturalOrder = true` — natural sort of columns/constraints on Relation view.
- `ForeignKeyMaxLimit = 100`, `ForeignKeyDropdownOrder = ['content-id','id-content']` — foreign dropdowns in Search/Zoom.
- `DefaultForeignKeyChecks = 'default'` (`default|enable|disable`) — pre-state of the "Enable foreign key checks" checkbox injected into DROP/TRUNCATE/DELETE confirmations.
- `RememberSorting = true` — Save column changes delete the remembered sort (`pma__table_uiprefs`) if the renamed column is part of it.
- Server-level (`src/Config/Settings/Server.php`): `tracking_version_auto_create = false`, `tracking_default_statements = 'CREATE TABLE,ALTER TABLE,DROP TABLE,RENAME TABLE,CREATE INDEX,DROP INDEX,INSERT,UPDATE,DELETE,TRUNCATE,REPLACE,CREATE VIEW,ALTER VIEW,DROP VIEW,CREATE DATABASE,ALTER DATABASE,DROP DATABASE'`, `tracking_add_drop_view = true`, `tracking_add_drop_table = true`, `tracking_add_drop_database = true`, `DisableIS` (use `SHOW` statements instead of `information_schema`).

## Screens / components

### Table tab bar (`src/Menu.php::getTableTabs()`)

Tabs, in order, with visibility rules:

1. **Browse** (`b_browse`, route `/sql`, arg `pos=0`) — always.
2. **Structure** (`b_props`, `/table/structure`) — always; active for `/table/structure` and `/table/relation`.
3. **SQL** (`b_sql`, `/table/sql`) — always.
4. **Search** (`b_search`, `/table/search`) — always; active for `/table/search`, `/table/zoom-search`, `/table/find-replace`.
5. **Insert** (`b_insrow`, `/table/change`) — only if not a system schema and (not a view OR an updatable view) (`Table::isUpdatableView()`).
6. **Export** (`b_tblexport`, `/table/export`, arg `single_table=true`) — always.
7. **Import** (`b_tblimport`, `/table/import`) — not for views, not for system schemas.
8. **Privileges** (`s_rights`, `/table/privileges`) — if (super user OR GRANT/CREATE USER privilege) and not a system schema.
9. **Operations** (`b_tblops`, `/table/operations` for tables, `/view/operations` for views) — not for system schemas.
10. **Tracking** (`eye`, `/table/tracking`) — if `Tracker::isActive()` (pmadb tracking feature configured) and not a system schema.
11. **Triggers** (`b_triggers`, `/triggers`) — if not system schema, current user has `TRIGGER` privilege on the table (`Util::currentUserHasPrivilege`) and not a view.

Secondary pill bar on Structure/Relation pages (`table/page_with_secondary_tabs.twig`): shown only if pmadb relation feature is on OR the engine supports foreign keys; pills "Table structure" (`/table/structure`) and "Relation view" (`/table/relation`), both `disableAjax`. Below the pills: flash messages then `<div id="structure_content">`.

### Structure tab (`/table/structure`)

**Purpose.** List columns, manage per-column actions, bulk actions, add columns, manage indexes, partitions and show table statistics.

**Controller flow** (`StructureController::__invoke`): `PageSettings::init('TableStructure')` (page-settings modal), adds script `table/structure.js`, validates db/table (ajax → `{success:false,message:'No database selected.'|'No table selected.'}`; non-ajax → redirect `/` with `reload=true`), gathers primary index (`Index::getPrimary`), columns with any index (`Table::getColumnsWithIndex(UNIQUE|INDEX|SPATIAL|FULLTEXT)`), `dbi->getColumns()`, then `displayStructure()`.

`displayStructure()` details:
- View detection: `tbl_is_view` → engine label "View"; else `strtoupper(getStorageEngine())`.
- Comments map from `pma__column_info` only when `ShowPropertyComments`; MIME map only if browser transformation feature + `BrowseMIME`.
- Central columns: `CentralColumns::findExistingColNames(db, columnNames)` → `central_list`.
- Table stats HTML computed if `ShowStats` and also returned as JSON `tableStat` (used by JS after drop-column to refresh `#tablestatistics`).
- Per row: `Util::extractColumnSpec(type)` → `attribute` (BINARY / UNSIGNED / UNSIGNED ZEROFILL / COMPRESSED=zlib), overridden to `on update CURRENT_TIMESTAMP` if `Extra` contains it; icons `b_primary` (Primary) / `bd_primary` (Index) appended after column name; collation resolved via `Charsets::findCollationByName` (name + description tooltip).
- Also passes `indexes` (`Index::getFromTable`), `indexes_duplicates` (`Index::findDuplicates` notice HTML), `have_partitioning`, `partitions`, `partition_names`, `default_sliders_state`, `mysql_int_version`, `is_mariadb`, `is_active` (tracking), `hide_structure_actions`, `is_foreign_key_supported`.

**Server-side SQL**

`Table::generateFieldSpec(name, type, length, attribute, collation, null, defaultType, defaultValue, extra, comment, virtuality, expression, moveTo, columnsWithIndex, oldColumnName)` builds one column definition:
- `` `name` TYPE `` + `(length)` unless type ∈ `DATE|TINYBLOB|TINYTEXT|BLOB|TEXT|MEDIUMBLOB|MEDIUMTEXT|LONGBLOB|LONGTEXT|SERIAL|BOOLEAN|UUID|JSON` or (MySQL ≥ 8.0.18 and type is SMALLINT/MEDIUMINT/INT/BIGINT, or TINYINT with length ≠ 1).
- ` ATTRIBUTE` (and for TIMESTAMP with `on update CURRENT_TIMESTAMP` appends `(length)` fractional precision).
- Charset part for TINYTEXT/TEXT/MEDIUMTEXT/LONGTEXT/VARCHAR/CHAR/ENUM/SET when collation given and ≠ `NULL` (`Util::getCharsetQueryPart(collation, true)` → ` CHARACTER SET x COLLATE x_y`); for MariaDB virtual columns on unsupported versions only `CHARACTER SET` is kept.
- Virtual: ` AS (expression) VIRTUAL|STORED|PERSISTENT`.
- `NULL`/`NOT NULL` (skipped for MariaDB virtual columns; MySQL virtual columns keep NULL/extra).
- Default (non-virtual only): `USER_DEFINED` → TIMESTAMP `'0'` → `DEFAULT 0`; TIMESTAMP literal `'YYYY-MM-DD HH:MM:SS[.ffffff]'` kept raw; BIT → `DEFAULT b'0101'` (non-0/1 chars → 0); BOOLEAN → `DEFAULT TRUE|FALSE` by `/^1|T|TRUE|YES$/i` / `/^0|F|FALSE|NO$/i`; BINARY/VARBINARY → `DEFAULT 0x{hex}`; `uuid_v4()`/`uuid_v7()`/`unix_timestamp()` raw; values starting with `current_timestamp` → `DEFAULT CURRENT_TIMESTAMP(length)`; else quoted string. `NULL` → `DEFAULT NULL` (only if Null checked; otherwise ignored). `CURRENT_TIMESTAMP` → `DEFAULT CURRENT_TIMESTAMP[(length)]`. `UUID`→`DEFAULT uuid()`, `UUID_v4`→`uuid_v4()`, `UUID_v7`→`uuid_v7()`. `NONE` → nothing.
- ` AUTO_INCREMENT` (extra; stripped for virtual columns).
- ` COMMENT 'x'`.
- ` FIRST` for moveTo `-first`, ` AFTER `col`` otherwise.
- If AUTO_INCREMENT and the (old) column is not already in a PRIMARY/UNIQUE index: appends `, ADD PRIMARY KEY (`name`)`.

`Table::generateAlter(oldcol, …)` = `` `oldcol` `` + `generateFieldSpec(...)` (used as `CHANGE `old` `new` …`).

- **Create table** (`CreateController`, `CreateAddField::getTableCreationQuery`): `CREATE TABLE `db`.`t` (<col defs>, PRIMARY KEY (`a`, `b`(10)), INDEX `name` (`c`) KEY_BLOCK_SIZE = 8 USING BTREE COMMENT 'x', UNIQUE …, FULLTEXT … WITH PARSER ngram, SPATIAL …) ENGINE = InnoDB CHARACTER SET x COLLATE x_y CONNECTION = '…' COMMENT = '…' PARTITION BY …;` Index definitions come from the JSON hidden inputs (`buildIndexStatement`: key name omitted for PRIMARY; sub-part `(size)`; `USING` only for non-SPATIAL/FULLTEXT with type in BTREE/HASH; `WITH PARSER` only for FULLTEXT). Lower-case db/table when `lower_case_table_names=1`. Refuses if table exists ("Table %s already exists!") or DB doesn't exist. `preview_sql` returns `sql_data`. After success stores MIME via `Transformations::setMime` per column. Field count: `num_fields` (default 4), capped at 4096.
- **Add column** (`AddFieldController`, `getColumnCreationQuery`): `ALTER TABLE `t` ADD `c` … [FIRST | AFTER `x`], ADD `c2` … AFTER `c`, ADD INDEX … [, ALGORITHM=INPLACE, LOCK=NONE];` — only the first new column honours `field_where` (`first`/`after`/`last`); subsequent ones go `AFTER` the previous new column. Success: message "Table %1$s has been altered successfully." + `structure_refresh_route`. `num_fields` capped at 4096, default 1.
- **Change columns** (`Structure\SaveController::updateColumns`): for each posted column where `columnNeedsAlterTable` (name differs, or any of attribute/collation/comments/default_value/default_type/extra/length/null/type/virtuality differs from `_orig`, or `field_move_to` set): `CHANGE `old` `new` …`. Combined: `ALTER TABLE `t` CHANGE …, CHANGE … [, ALGORITHM=INPLACE, LOCK=NONE];`. Before running, for columns whose collation changed and which are not indexed, a temporary conversion `ALTER TABLE `t` CHANGE `c` `c` BLOB|MEDIUMBLOB|LONGBLOB [AS (expr) VIRTUAL];` is executed (to avoid charset conversion garbling); on failure of the main ALTER the original definitions are restored with another `ALTER TABLE … CHANGE …` and the error is shown ("Query error:<br>…"), `regenerate=true`. On success: "Table %1$s has been altered successfully." (+ " Privileges have been adjusted." when `field_adjust_privileges` and names changed → `UPDATE mysql.columns_priv SET Column_name="new" WHERE Db=… AND Table_name=… AND Column_name="old"; FLUSH PRIVILEGES;`). Always: `Relation::renameField()` for renamed columns (pmadb relation/column_info/table_uiprefs), `Transformations::setMime()` per column when `BrowseMIME`, and removal of the remembered `sorted_col` ui-pref if it referenced the old name. `preview_sql` → `sql_data` (empty string if no change, rendered "No change").
  - Found by the golden suite: the `_orig` snapshot comes from `ColumnsDefinition::displayForm` and differs from what the form shows for several columns, so an *untouched* column is still re-stated with `CHANGE`: A_I columns (`field_extra` "AUTO_INCREMENT" vs `_orig` "auto_increment"), `DEFAULT CURRENT_TIMESTAMP` columns (`field_default_value` '' vs `_orig` "CURRENT_TIMESTAMP"), `on update` columns (attribute shown, `_orig` empty; MySQL 8 `Extra` "DEFAULT_GENERATED …"), generated columns (`field_virtuality_orig` is always ''). The change form always posts the column's collation, so the CHANGE carries `CHARACTER SET … COLLATE …`. When the main ALTER fails the revert query runs even without BLOB conversions (`ALTER TABLE `t` ;`, which itself fails). "Adjust privileges" is ticked by default when the user has column privileges + RELOAD; a rename then runs `USE mysql` + `UPDATE `columns_priv` …` + `FLUSH PRIVILEGES;`.
  - The /sql links of the Structure page (drop column, drop index / primary key, remove partitioning) are posted with `fk_checks=0`: `SET FOREIGN_KEY_CHECKS = OFF;` before and `= ON;` after the statement; dropping a column there also runs `Transformations::clear` (`DELETE FROM pmadb.column_info WHERE `db_name` = '…' …`, unescaped, on the user's connection) when the browser-transformation feature is configured.

### Index editor dialog (`/table/indexes`) and Index rename (`/table/indexes/rename`)

**Purpose.** Create or edit one index (PRIMARY/INDEX/UNIQUE/SPATIAL/FULLTEXT) with N columns, sub-parts, sort order, type, parser, block size and comment; rename an index.

**Opening.** From Structure: "Edit" (POST `index=<name>`), footer "Create an index on N columns" (POST `create_index=1&added_fields=N`), from the column-definition form (`create_edit_table=1`), or from the navigation panel (`is_from_nav=1` adds hidden `do_save_data` and the `modals/preview_sql_modal.twig`). Shown inside `#indexDialogModal` (title "Add index" / "Edit index"), footer **Go** / **Preview SQL** / **Close**; when rendered standalone the form has its own **Go** + **Preview SQL** (`#preview_index_frm`) footer.

**Controls** (`table/index_form.twig`, `#index_frm`):
- **Index name:** `<input name="index[Key_name]" id=input_index_name size=25 maxlength=64 onfocus=select>` + hint `"PRIMARY" must be the name of and only of a primary key!`. JS `checkIndexName`: when choice is PRIMARY the name is forced to `PRIMARY` and disabled (re-enabled on submit so it posts); otherwise a name `PRIMARY` is cleared.
- **Index choice:** `<select name="index[Index_choice]" id=select_index_choice>` (disabled in create_edit_table mode) options: `PRIMARY` (only if editing the PK or table has no PK — `index.hasPrimary()`), `INDEX`, `UNIQUE`, `SPATIAL`, `FULLTEXT` + doc `ALTER_TABLE`. A *new* index (`create_index`) is `new Index()`: `Non_unique` defaults to false, so the preselected choice is **UNIQUE**, and `hasPrimary()` looks up the new index's empty schema/table, so **PRIMARY is always offered** for a new index even when the table has one (verified against the reference). Editing an existing index re-posts its `Index_type` (`USING BTREE` is added) and its collation letters (`A` → ` ASC`), `Key_block_size` shows `0` (omitted). There is no index visibility control in phpMyAdmin.
- **Advanced options** collapse (unless `InitialSlidersState = disabled`): **Key block size** `<input name="index[Key_block_size]" size=30>`; **Index type** `<select name="index[Index_type]" id=select_index_type>` options `''`, `BTREE`, `HASH`; **Parser** `<input name="index[Parser]" size=30>`; **Comment** `<input name="index[Index_comment]" size=30 maxlength=1024>`.
- Columns table `#index_columns`: header (drag) | Column | Size | Collation. One row per existing index column + `add_fields` new rows: drag handle `span.drag_icon` (title "Drag to reorder"; tbody sortable with cell-width-preserving helper), `<select name="index[columns][names][]">` ("-- Ignore --" + `name [type]`; for FULLTEXT only `/(char|text)/i` types; for SPATIAL only spatial types), `<input name="index[columns][sub_parts][]" size=5>` (blank for SPATIAL), `<select name="index[columns][collations][]">` `None` / `A` (ASC) / `D` (DESC). New rows preselect the i-th column.
- `.add_more`: jQuery-UI slider (1..16) + submit `#add_fields` "Add %s column(s) to index" (posts `add_fields` to re-render with extra rows).
- `checkIndexType()`: for SPATIAL hides Size column, disables all but the first column row and hides add-more; for SPATIAL/FULLTEXT disables Index type.
- On choosing a column, focus jumps to its Size input; index name input focused if empty.

**Server-side** (`IndexesController`, `Table\Indexes::getSqlQueryForIndexCreateOrEdit`): `ALTER TABLE `db`.`t` [DROP PRIMARY KEY, | DROP INDEX `old`,] ADD PRIMARY KEY | ADD INDEX|UNIQUE|SPATIAL|FULLTEXT [`name`] (`c1`(10) ASC, `c2` DESC) [KEY_BLOCK_SIZE = n] [USING BTREE|HASH] [WITH PARSER x] [COMMENT 'x'];` — `USING` omitted for SPATIAL/FULLTEXT and for TokuDB tables. Errors: "The name of the primary key must be "PRIMARY"!", "Can't rename index to PRIMARY!", "No index parts defined!" (returned as `{success:false,message}` before executing). Column count for new index capped at 16 (`min(added_fields,16)`). AJAX success returns `message` ("Table %1$s has been altered successfully." + SQL) and `index_table` (re-rendered `indexes.twig`). Non-ajax falls through to the Structure page.

**Rename** (`IndexRenameController`, `index_rename_form.twig`): form with only **Index name** (`<input name=index>`) and **Preview SQL** footer (Go is in the modal). SQL: `ALTER TABLE `db`.`t` RENAME INDEX `old` TO `new`;` when `Compatibility::isCompatibleRenameIndex` (MySQL ≥ 5.7 / MariaDB ≥ 10.5.2), else drop+recreate via `getSqlQueryForIndexCreateOrEdit`. Same PRIMARY name errors.

### Find and replace (`/table/find-replace`)

**Layout** (`table/find_replace/index.twig`): pill bar; form `#find_replace_form.ajax.lock-page` card "Find and replace": **Find:** `<input name=find required>`, **Replace with:** `<input name=replaceWith>`, **Column:** `<select name=columnIndex>` (only columns whose type class is Char — `Types::getTypeClass == Char`), **Use regular expression** checkbox `useRegex`; **Go**. **Flow**: submit (AJAX, has `find`) → server returns `preview` HTML (`replace_preview.twig`): hidden form (`replace=true`, `columnIndex`, `findString`, `replaceWith`, `useRegex`) card "Find and replace - preview" with table Count | Original string | Replaced string and footer **Replace**; JS shows a "Hide/Show find & replace criteria" toggle and collapses the form. Submitting the preview form (non-AJAX POST with `replace`) performs the update, shows a success message and re-renders the criteria form.

**SQL**:
- Preview (plain): `SELECT `c`, REPLACE(`c`, 'find', 'repl'), COUNT(*) FROM `db`.`t` WHERE `c` LIKE '%find%' COLLATE {connection_charset}_bin GROUP BY `c` ORDER BY `c` ASC` (wildcards in `find` escaped; binary collation forces case-sensitivity).
- Preview (regex): `SELECT `c`, 1, COUNT(*) FROM `db`.`t` WHERE `c` RLIKE 'find' COLLATE cs_bin GROUP BY `c` ORDER BY `c` ASC`, then PHP `preg_replace` per distinct value using the first delimiter from `/ @ # ~ ! $ % ^ & _` not present in the pattern (returns `false`/no rows if none fits).
- Replace (plain): `UPDATE `t` SET `c` = REPLACE(`c`, 'find', 'repl') WHERE `c` LIKE '%find%' COLLATE cs_bin`.
- Replace (regex): `UPDATE `t` SET `c` = CASE\n WHEN `c` = 'orig1' THEN 'new1' … END WHERE `c` RLIKE 'find' COLLATE cs_bin` (or `SET `c` = `c`` when nothing matched).
